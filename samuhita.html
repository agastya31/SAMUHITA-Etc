Fase 1–2 · Discovery
Gunakan Strategy.P2P_CLUSTER agar setiap perangkat bisa bertindak sebagai advertiser dan discoverer secara bersamaan. Ini yang memungkinkan mesh routing.

onEndpointLost() dipanggil saat peer keluar dari jangkauan — langsung update DB ke status offline dan hapus dari daftar radar.
Fase 3–5 · Pairing (Challenge-Response)
Saat onConnectionInitiated() dipanggil, kirim nonce 32 byte random ke peer. Peer harus membalas dengan HMAC-SHA256(nonce, sharedKey). Jika verifikasi berhasil, panggil acceptConnection().

Tampilkan kode PIN 6 digit visual agar user bisa konfirmasi secara out-of-band bahwa koneksi yang benar.
Fase 6 · Session — Transport Otomatis
Jangan paksa transport secara manual. Nearby API otomatis memilih:
• Payload.Type.BYTES → Bluetooth (teks, < 32 KB)
• Payload.Type.FILE → Wi-Fi Direct (foto/video)

Pastikan semua permission runtime sudah granted sebelum memanggil startDiscovery().
Fase 7 · Disconnect & Reconnect
Implementasikan exponential backoff untuk reconnect: 5s → 10s → 20s → 40s → max 5 menit. Gunakan WorkManager dengan constraint requiresNetworkType(NOT_REQUIRED) untuk background reconnect tanpa menguras baterai.

Pesan yang gagal terkirim saat disconnect disimpan dengan status FAILED dan diretry otomatis saat koneksi kembali.
Adaptive Scan Scheduler — Battery Management
KOTLINAdaptiveScanScheduler.kt — Duty Cycle
enum class ScanMode(val intervalMs: Long, val durationMs: Long) { FOREGROUND (0L, Long.MAX_VALUE), // aktif terus BACKGROUND_ACTIVE(60_000, 10_000), // 10s per 1 menit BACKGROUND_IDLE (300_000, 5_000), // 5s per 5 menit DOZE_MODE (0, 0) // stop total } fun onAppBackground() = applyScanMode(ScanMode.BACKGROUND_ACTIVE) fun onScreenOff() = applyScanMode(ScanMode.BACKGROUND_IDLE) fun onDozeEnter() = applyScanMode(ScanMode.DOZE_MODE) fun onForeground() = applyScanMode(ScanMode.FOREGROUND)
